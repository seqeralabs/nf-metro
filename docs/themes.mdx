A theme decides how a map looks: colors, fonts, station glyphs, section boxes, the legend frame, and optionally layout spacing.
It never changes what the map says.

Looking for how one SVG adapts to light and dark viewers? See [Light and dark mode](/nf-metro/light-dark/).

## Concepts

**Theme.** A named set of [fields](#field-reference), written as a YAML file.
Every built-in theme is such a file in `src/nf_metro/themes/`, loaded and checked exactly like one you write yourself.

**Mode.** A theme has a light and a dark palette of colors; sizes and shapes are the same in both.
An SVG carries both and follows the viewer's `color-scheme` (see [Light and dark mode](/nf-metro/light-dark/)).
`%%metro mode:` or `--mode` picks the palette baked into a PNG or a single-palette export.
A theme whose colors match in both palettes renders the same in either.

**Stack.** A theme value is a comma-separated list of themes, applied left to right.
A later theme wins for every field it sets, and the light and dark palettes merge separately.
A single name is a stack of one.

**Base.** Every stack starts from the `default` theme, so a theme only needs to set the fields it changes.
A map with no `%%metro style:` renders with `default` alone.

**Layout block.** A theme can also set some layout options, such as spacing.
The order of precedence is: a command-line flag, then a `%%metro` directive in the map, then the theme, then the built-in default.

## Using a theme

Set the theme in the map, or on the command line:

```text
%%metro style: london-tube
```

```bash
nf-metro render pipeline.mmd -o pipeline.svg --theme london-tube
```

`--theme` replaces the map's `%%metro style:` entirely, so `--theme default` renders a map in the base theme whatever its own style says.
`--mode light` or `--mode dark` picks the palette a PNG bakes.

### london-tube

After TfL's [Line Diagram Standard](https://content.tfl.gov.uk/tfl-line-diagram-standard.pdf) and [Colour Standard](https://content.tfl.gov.uk/tfl-colour-standard.pdf): tabs in the line's color at one-line stations, bold capsules at interchanges, a buffer-stop bar at line ends, bundled lines edge to edge, unboxed dashed sections, station names in TfL Corporate Blue, and the TfL line colors.

```yaml
station_glyph: tick
interchange_glyph: pill
terminus_glyph: bar
layout: { curve_radius_ratio: 3.5 }
```

### nyc-subway

After Massimo Vignelli's 1972 diagram and its 2008 revival: every line its own color with only a hairline between them, a small solid black dot wherever a line stops, no separate interchange symbol, tight corners, Helvetica in black, and the legend as round route bullets.
The palette is the MTA's published route colors.
In dark mode it takes the white-on-black of the 1970 Graphics Standards Manual's sign panels.

## Line colors

A theme's `line_colors` gives the map's lines their colors, in the order the map declares them.
A map with more lines than the list gets a generated color for each extra line: the color farthest, in the perceptual OKLab space, from every color already in use (the palette, earlier extras, the background and the inactive grey), among those readable at 3:1 on the light background.
In dark mode each generated color is the same hue, lightened to 3:1 on the dark background, so a line keeps its identity across modes.
The palette's own colors are never changed, and the same map always gets the same extras.
Without it, each line keeps the color from its `%%metro line:` directive.

Set `line_colors` at the top level for both palettes, or under `light:` and `dark:` to give each its own.
`london-tube` does both: the TfL colors in light mode, and in dark mode the same list with the Piccadilly, Metropolitan and Elizabeth colors lightened to stay readable, and the black Northern line turned near-white.
A line whose two palette colors differ follows the viewer's mode in an SVG, as the chrome does.

To keep a built-in theme's look but your map's own line colors, stack a file that empties the list:

```yaml title="my_colours.yaml"
name: my-colours
line_colors: []
```

```text
%%metro style: london-tube, my_colours.yaml
```

## Station glyphs

Three fields pick how a station is drawn.
The last column names a theme above that draws each one.

| Field               | Value      | Draws                                                                                      | See                                             |
| ------------------- | ---------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| `station_glyph`     | `pill`     | a capsule                                                                                  | `default`                                       |
| (one line)          | `tick`     | a tab in the line's color, on the label's side                                             | `london-tube`                                   |
|                     | `dot`      | a dot on the line, sized by `dot_diameter` and outlined by `dot_ring_width` and `dot_ring` | `nyc-subway`, `paris-metro`, `washington-metro` |
|                     | `numbered` | a station-number marker ringed in the line's color                                         | `tokyo-metro`                                   |
| `interchange_glyph` | `pill`     | one capsule across all the lines                                                           | `default`, `london-tube`, `paris-metro`         |
| (several lines)     | `ring`     | a ring centred on the lines, or a bridged chain of them                                    | `london-tube` with rings                        |
|                     | `dots`     | a dot on each line                                                                         | `nyc-subway`, `washington-metro`                |
|                     | `numbered` | one station-number marker across the lines, ringed in `station_stroke`                     | `tokyo-metro`                                   |
| `terminus_glyph`    | `nub`      | a square-cornered box across the lines                                                     | `default`                                       |
| (line end)          | `bar`      | a buffer-stop bar across the bundle                                                        | `london-tube`, `tokyo-metro`                    |
|                     | `ring`     | rings, or the `dots` or `numbered` interchange glyph when the theme uses one               | `nyc-subway`, `washington-metro`                |

A line end with one line follows `station_glyph`, and its file icon always sits beyond the glyph.

With `ring`, `ring_max_lines` is the most lines on one track that a single ring covers, and `ring_overflow` decides what a wider bundle gets: `chain`, the fewest touching rings that cover it, bridged by a strip in the station fill; or `grow`, one ring whose inside widens to cover it.
Lines on separate tracks, as at a cross-track `%%metro interchange:` or a rail-mode station, get separate rings joined by a dumbbell link.

The legend shows each line as a length of line, or with `legend_swatch: bullet` as a disc in its color carrying its code (`line_codes`: `letters` or `numbers`), in black or white, whichever reads better.

Corner radius is a layout option, `curve_radius_ratio`: the radius at the line centre as a multiple of the line width.
`london-tube` sets 3.5, the standard's three line widths to the inside edge of the line, so its 4 px lines bend at 14 px.
Unset, corners bend at 10 px, and `stroke_scale` scales the radius either way.

## Stacking themes

```text
%%metro style: seqera, london-tube
```

This map takes the station glyphs, section style, fonts and line colors from `london-tube`, and every field `london-tube` leaves unset from `seqera`.
Under both lies `default`, which supplies anything neither sets.
Every stack starts from `default`; list only the themes you add on top.

A built-in theme sets only the fields its file lists.
`london-tube, seqera` therefore keeps the `london-tube` station tabs and capsules, because `seqera` does not set `station_glyph` or `interchange_glyph`, but takes the `seqera` colors and fonts.

## Writing your own theme

1. Create a YAML file whose name ends in `.yaml` or `.yml`.
2. Give it a `name`, then set the fields you want to change.
   Top-level fields apply to both palettes, and `light:` and `dark:` blocks override colors (and `line_colors`) for one palette.
   Sizes and shapes are top-level only, because a map is laid out once for both palettes.
3. Optionally, start from another theme with `extends:`, and set layout options in a `layout:` block.
4. Add the file to a stack.
   In `%%metro style:` the path is relative to the `.mmd` file; on the command line it is relative to the working directory.

```yaml title="house_style.yaml"
# yaml-language-server: $schema=https://raw.githubusercontent.com/seqeralabs/nf-metro/main/src/nf_metro/themes/theme.schema.json
name: house-style
extends: london-tube # optional: a name, a file, or a list

label_font_size: 13
station_glyph: tick

light:
  label_color: "#5a2d82"
  legend_stroke: "#5a2d82"
dark:
  label_color: "#e5d4f5"
  legend_stroke: "#e5d4f5"

layout:
  y_spacing: 45
```

```text
%%metro style: house_style.yaml
```

`extends:` is shorthand for listing those themes earlier in the stack, so the line above is the same as `%%metro style: london-tube, house_style.yaml`.
A theme without `extends:` sits directly on `default`, like every stack.

A color left empty takes the field its description names: icon and badge colors take the station colors, the marker outline and station-number codes take `station_stroke`, and `knockout_fill` (label halos and `open` markers) takes the background, or white on a transparent canvas.

nf-metro checks the whole file against the theme's JSON Schema before it renders anything.
An unknown field, a value of the wrong type or out of range (including `.inf` and `.nan`), a color it cannot read, a size inside `light:` or `dark:`, an unknown `layout:` option, or two files that extend each other stops the render with an error that names the file and the path to the bad value, such as `$.light.label_color`.
Font families, font weights and dash patterns accept only the characters CSS needs for them.

The schema ships with nf-metro as `nf_metro/themes/theme.schema.json` and is generated from the same definitions as the field reference below.
The first line of the example above points editors that use the YAML language server (VS Code's YAML extension, for one) at it, so they complete field names and flag mistakes as you type.
Any other JSON Schema tool can validate a theme file against it too.

### Fonts

The SVG names the theme's font and the viewer's browser draws it, so name a font your readers have, followed by fallbacks.
The transit themes ask for the faces their standards use (Gill Sans standing in for Johnston, Helvetica, Parisine, Frutiger) and fall back to common sans faces.
PNG output, `--embed-font` and `--text-to-paths` draw every theme in the bundled Inter face, so the output is the same on any machine.

## Field reference

Every field of the `Theme` schema (`src/nf_metro/render/style.py`) can be set in a theme file.
**Default** is the schema's own default, which the `default` theme overrides for some fields.
A **colour** is a hex value, an `rgb()`/`hsl()` function, a CSS color name, `transparent` or `none`.
