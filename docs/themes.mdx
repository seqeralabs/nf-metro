A theme decides how a map looks: colors, fonts, station glyphs, section boxes, the legend frame, and optionally layout spacing.
It never changes what the map says.

Looking for how one SVG adapts to light and dark viewers? See [Light and dark mode](/nf-metro/light-dark/).

## Concepts

**Theme.** A named set of [fields](#field-reference), written as a YAML file.
Every built-in theme is such a file in `src/nf_metro/themes/`, loaded and checked exactly like one you write yourself.

**Mode.** A theme has a light and a dark palette of colors; sizes and shapes are the same in both.
An SVG carries both and follows the viewer's `color-scheme` (see [Light and dark mode](/nf-metro/light-dark/)).
`%%metro mode:` or `--mode` picks the palette baked into a PNG or a single-palette export.
A theme whose colors match in both palettes renders the same in either.

**Stack.** A theme value is a comma-separated list of themes, applied left to right.
A later theme wins for every field it sets, and the light and dark palettes merge separately.
A single name is a stack of one.

**Base.** Every stack starts from the `default` theme, so a theme only needs to set the fields it changes.
A map with no `%%metro style:` renders with `default` alone.

**Layout block.** A theme can also set some layout options, such as spacing.
The order of precedence is: a command-line flag, then a `%%metro` directive in the map, then the theme, then the built-in default.

## Using a theme

Set the theme in the map, or on the command line:

```text
%%metro style: london-tube
```

```bash
nf-metro render pipeline.mmd -o pipeline.svg --theme london-tube
```

`--theme` replaces the map's `%%metro style:` entirely, so `--theme default` renders a map in the base theme whatever its own style says.

| Theme         | Look                                                                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `default`     | The base every stack starts from: bold labels, filled section boxes with number badges, white station pills.                                                                          |
| `seqera`      | Seqera brand colors and Inter type.                                                                                                                                                   |
| `london-tube` | A schematic transit look: track-weight tabs for one-line stations, bold capsules at interchanges, bundled lines edge to edge, corners bending at three line widths, unboxed sections. |
| `transparent` | One palette on a transparent canvas, for embedding. Looks the same in either mode.                                                                                                    |

`--mode light` or `--mode dark` picks the palette a PNG bakes.

## Stacking themes

```text
%%metro style: seqera, london-tube
```

This map takes the station glyphs, section style and fonts from `london-tube`, and every field `london-tube` leaves unset from `seqera`.
Under both lies `default`, which supplies anything neither sets.
Every stack starts from `default`; list only the themes you add on top.

A built-in theme sets only the fields its file lists.
`london-tube, seqera` therefore keeps the `london-tube` station tabs and capsules, because `seqera` does not set `station_glyph` or `interchange_glyph`, but takes the `seqera` colors and fonts.

## Writing your own theme

1. Create a YAML file whose name ends in `.yaml` or `.yml`.
2. Give it a `name`, then set the fields you want to change.
   Top-level fields apply to both palettes, and `light:` and `dark:` blocks override colors for one palette.
   Sizes and shapes are top-level only, because a map is laid out once for both palettes.
3. Optionally, start from another theme with `extends:`, and set layout options in a `layout:` block.
4. Add the file to a stack.
   In `%%metro style:` the path is relative to the `.mmd` file; on the command line it is relative to the working directory.

```yaml title="house_style.yaml"
# yaml-language-server: $schema=https://raw.githubusercontent.com/seqeralabs/nf-metro/main/src/nf_metro/themes/theme.schema.json
name: house-style
extends: london-tube # optional: a name, a file, or a list

label_font_size: 13
station_glyph: tick

light:
  label_color: "#5a2d82"
  legend_stroke: "#5a2d82"
dark:
  label_color: "#e5d4f5"
  legend_stroke: "#e5d4f5"

layout:
  y_spacing: 45
```

```text
%%metro style: house_style.yaml
```

`extends:` is shorthand for listing those themes earlier in the stack, so the line above is the same as `%%metro style: london-tube, house_style.yaml`.
A theme without `extends:` sits directly on `default`, like every stack.

A color left empty takes the field its description names: icon and badge colors take the station colors, the marker outline takes `station_stroke`, and `knockout_fill` (label halos and `open` markers) takes the background, or white on a transparent canvas.

nf-metro checks the whole file against the theme's JSON Schema before it renders anything.
An unknown field, a value of the wrong type or out of range (including `.inf` and `.nan`), a color it cannot read, a size inside `light:` or `dark:`, an unknown `layout:` option, or two files that extend each other stops the render with an error that names the file and the path to the bad value, such as `$.light.label_color`.
Font families, font weights and dash patterns accept only the characters CSS needs for them.

The schema ships with nf-metro as `nf_metro/themes/theme.schema.json` and is generated from the same definitions as the field reference below.
The first line of the example above points editors that use the YAML language server (VS Code's YAML extension, for one) at it, so they complete field names and flag mistakes as you type.
Any other JSON Schema tool can validate a theme file against it too.

### Interchange styles

A station on several lines is an interchange.
`interchange_glyph` picks how it is drawn:

- `pill` (the default) draws one capsule across all its lines, in `station_fill` and `station_stroke`.
- `ring` draws a ring centred on the lines, outlined in `station_stroke` and filled with `station_fill`.

With `ring`, `ring_max_lines` is the most lines on one track that a single ring covers, and `ring_overflow` decides what a wider bundle gets:

- `chain` draws the fewest rings that cover the bundle, centred on it, each ring's outer edge meeting the next ring's inner edge, with a strip in the station fill cut through the outlines where they meet so the centres join into one shape.
  The spacing never changes, so every chain has the same neck, and a chain can reach a little past the outermost lines.
- `grow` draws one ring whose inside widens to cover the whole bundle.

So the three styles are: one standard-size ring (raise `ring_max_lines`), a bridged chain (`chain`), or one larger ring (`grow`).
Lines on separate tracks, as at a cross-track `%%metro interchange:` or a rail-mode station, get separate rings joined by a dumbbell link.
`london-tube` draws a white capsule with a heavy black outline (a light outline round a dark capsule in dark mode) and a `bar` at every line end.
The Line Diagram Standard's own idiom is rings, which a theme extending `london-tube` gets with `interchange_glyph: ring`: one ring for two lines, and a chain from three up.

Corner radius is a layout option, `curve_radius_ratio`: the radius at the line centre as a multiple of the line width. `london-tube` sets `layout: {curve_radius_ratio: 3}`, so its 4 px lines bend at 12 px. Unset, corners bend at 10 px, and `stroke_scale` scales the radius either way.

A line end shared by several lines follows `terminus_glyph` instead:

- `nub` (the default) draws a square-cornered box across the lines in the station colours.
- `bar` draws a buffer-stop bar across the whole bundle, as thick as a station tab and overhanging the outermost lines by a tab's length, in `station_stroke`.
- `ring` draws the interchange glyph above.

A line end with one line follows `station_glyph`, and its file icon always sits beyond the glyph.

### Fonts

The SVG names the theme's font and the viewer's browser draws it, so name a font your readers have, followed by fallbacks.
`london-tube` asks for Gill Sans, which macOS and Windows with Office have.
PNG output, `--embed-font` and `--text-to-paths` draw every theme in the bundled Inter face, so the output is the same on any machine.

## The built-in themes

The built-in themes are the best worked examples of the format.
Each is a short file in [`src/nf_metro/themes/`](https://github.com/seqeralabs/nf-metro/tree/main/src/nf_metro/themes).

- `default.yaml` is the base.
  It sets every field the schema leaves without a default, so it is the template for a complete theme.
- `seqera.yaml` replaces the fonts, sizes and both palettes, and leaves the shapes alone.
- `london_tube.yaml` changes shapes as well as colors, and is the example to copy for a different look.
  Its geometry follows the construction rules of TfL's [Line Diagram Standard](https://content.tfl.gov.uk/tfl-line-diagram-standard.pdf), and the file's comments give the reasoning behind each choice.
- `transparent.yaml` sets every color at the top level, so both palettes match, with `background_fill: none`, for maps embedded on a page that supplies its own background.

```yaml title="london_tube.yaml (abridged)"
name: london-tube

station_glyph: tick
station_tick_width: 1 # track-weight tabs
station_tick_length: 1.5
interchange_glyph: pill # ring for the standard's rings
ring_max_lines: 2 # with ring: a chain from three lines up
terminus_glyph: bar
station_stroke_width: 2.5
line_width: 4
label_font_weight: normal
section_stroke_dasharray: "6 4"
number_sections: false
uppercase_section_labels: true
legend_stroke_width: 1.5

light:
  background_fill: "#ffffff"
  label_color: "#1c3f94"
  station_fill: "#ffffff"
  station_stroke: "#000000"
  muted_line_color: "#b3b3b3"
  section_fill: transparent
  legend_stroke: "#000000"
dark:
  background_fill: "#10141c"
  label_color: "#dfe6ff"
  station_fill: "#10141c"
  station_stroke: "#ffffff"
  muted_line_color: "#585a60"
  section_fill: transparent
  legend_stroke: "#ffffff"
```

## Field reference

Every field of the `Theme` schema (`src/nf_metro/render/style.py`) can be set in a theme file.
**Default** is the schema's own default, which the `default` theme overrides for some fields.
A **colour** is a hex value, an `rgb()`/`hsl()` function, a CSS color name, `transparent` or `none`.

### Layout options

A `layout:` block takes these options, with the same values as their `%%metro` directives: `x_spacing`, `y_spacing`, `section_x_gap`, `section_y_gap`, `section_x_padding`, `section_y_padding`, `track_gap`, `diamond_style`, `line_order`, `row_align`, `center_ports`, `compact_offsets`, `label_angle`, `label_offset`, `diagonal_run`, `curve_radius_ratio`, `font_scale`, `stroke_scale`, `logo_scale`, `legend_min_height`, `legend_logo_gap`, `directional`. A theme's value applies only where the map has no directive for that option, and a command-line flag beats both.
