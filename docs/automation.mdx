---
title: "CI and automation"
description: Keep a pipeline's metro-map SVG in sync with its .mmd source using the nf-metro GitHub Action or pre-commit hook.
---

Commit a metro-map `.mmd` to your pipeline repo and let automation keep the rendered SVG in sync.
nf-metro ships two integrations:

- A composite GitHub Action that installs nf-metro and renders the map, leaving you to decide what to do with the result.
- A pre-commit hook that re-renders the SVG locally on every commit.

## GitHub Action

The composite action renders the map and reports what it wrote and whether anything changed.

```yaml
- uses: actions/checkout@v4
- uses: seqeralabs/nf-metro@2.1.0
  id: metro
  with:
    input: assets/metro_map.mmd
    theme: nfcore
    embed-font: "true"
# steps.metro.outputs.output-path — the path(s) written, one per line
# steps.metro.outputs.changed     — 'true' when any output differs from the committed version
```

Every input is optional:

- `input`: default `assets/metro_map.mmd`.
- `output`: default is the map's `%%metro output:` path(s), else the sibling `.svg`. Give several whitespace-separated paths to write more than one format in a single run, each taken from its extension: `output: "assets/metro_map.svg assets/metro_map.png"`.
- `theme`: default `nfcore`.
- `mode`: no default.
- `embed-font`: default `true`.
- `version`: the nf-metro version to install.
- `extra-args`: any other `nf-metro render` flag, such as `extra-args: "--fold-threshold 20"`.

When it writes more than one file, `output-path` lists them one per line and `changed` is `'true'` if any of them differs from what is committed.
The action reads these straight from nf-metro's own output, so declaring the paths with `%%metro output:` in the `.mmd` and leaving `output` empty renders and tracks every declared file.
The action always renders with `--reject-output-outside-source`, so a `%%metro output:` declaration that resolves outside the `.mmd`'s own directory (an absolute path, or a `..` escape) fails the step instead of being written: a workflow rendering a `.mmd` it doesn't control (an external contributor's PR, say) can't be made to write, or steer a later commit or diff step, outside its own repository.

## Pre-commit hook

Re-render the SVG locally on every commit so it cannot drift from the source.

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/seqeralabs/nf-metro
    rev: 2.1.0
    hooks:
      - id: nf-metro
```

The hook matches `*.mmd` and writes the sibling `.svg`.
`assets/metro_map.mmd` becomes `assets/metro_map.svg`.
A map that declares `%%metro output:` paths instead writes those (for example an `.svg` and a `.png`), so a single commit keeps every declared file in sync.
It runs with `--theme nfcore --embed-font` by default.
Setting `args` replaces that whole list.
Repeat the flags you want to keep alongside the new one:

```yaml
- id: nf-metro
  args: [--theme, nfcore, --embed-font, --mode, light]
```

Drop `--theme nfcore` if the map picks its own brand with a `%%metro style:` directive, which the flag would otherwise override.
